# Repository purpose

This public repository publishes versioned Novalon House Studio downloads, illustrated release guides and curated verification records. The private source and owner update record are maintained in Novo-Home. Keep the application offline and account-free.

# Every future release

- Every released version must have matching public and private release pages. Publish downloads here and the source/update record in Novo-Home. This is a standing user requirement from 26 October 2026.
- Use current, actual screenshots captured from the exact released build with synthetic projects: the workspace overview, the new or changed workflow, and measured output where applicable. Add captions describing the visible behavior and the action a user can try. Do not use older-build screenshots to represent a new release.
- Both pages must contain clear feature/capability bullets, step-by-step usage instructions, **What's new in this version**, and **How to update safely**. Describe the precise additions, behavior changes, fixes and relevant limits compared with the prior version. The private page must also include owner-readable update history and source/verification details.
- Explain the actual manual download/update process, independent project-file backups, verified compatibility/migration behavior, and retaining the previous working release for rollback.
- Identify the version, built/tested platforms, exact package source commit, verification results and SHA-256 checksums. Documentation refreshes must retain the unchanged package's original source identity.
- Public screenshots and instructions must work without private-repository access. Never publish credentials, personal projects, recovery profiles, local caches, dependency folders, private machine paths or reference-product artwork. Use only curated synthetic material.
- Update the README's current-release summary and retain versioned notes. A release is not complete until both live pages have been read back, all current screenshot links render, and version/source/checksum information agrees with the tested packages.
- Preserve remote history, prior versions and published package assets. Do not force-push, move existing version tags or replace published packages to refresh their presentation. Put application packages in GitHub Release assets rather than Git history.
- Publish Android APK or iOS IPA downloads only when those targets exist and have been built and tested. Never label a Windows package as a mobile build.

# Working style

Double-check claims against current implementation and verification evidence. Explain supported scope and remaining limits accurately. Keep approved edits undoable and preserve originals.
